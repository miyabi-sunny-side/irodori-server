# 構成

irodori-server は Rust (axum) のサーバーと Svelte 5 の画面、推論を担う Python の推論エンジンでできています。

```text
ブラウザ ── HTTP ── irodori-server (Rust)
                     ├─ data/irodori.sqlite3    生成の記録・参照音声・読み辞書
                     ├─ data/audio/*.wav        生成した音声
                     ├─ data/references/*       アップロードした参照音声
                     └─ HTTP (IRODORI_ENGINE_URL) ── 推論エンジン: .venv/bin/python irodori_engine.py
                                                      └─ Irodori-TTS (固定 revision) の _run_generation
```

推論エンジンは別のマシンで動かせます。家庭内では GPU のある homeserver のエンジンを、
homeserver の本番サーバーと sandbox の開発用サーバーの両方が使います。

## 推論エンジン

推論エンジン `irodori_engine.py` は Python 標準ライブラリの `http.server` で動く HTTP サーバーです。
モデルはエンジンの中に常駐し、2 回目以降の生成は読み込みを省きます。契約は [api.md](api.md#推論エンジン) にあります。

- エンジンは単一スレッドで要求を 1 件ずつ処理します。複数のサーバーから同時に呼ばれても、
  GPU とモデルは 1 つのまま順番待ちになります。
- 境界にファイルパスを通しません。参照音声は要求に、生成した WAV は応答に base64 で載せます。
  エンジンは受け取った音声と生成物を要求ごとの一時ディレクトリに置き、応答前に消します。
  一時ファイル名はエンジンが決め、拡張子は英小文字と数字の 8 文字までに限ります。
- 要求の処理中にエンジンの標準出力・標準エラーへ出たもの (upstream のログ、例外の trace) を
  `engine_log` として応答に載せ、エンジンの標準エラーにも残します。サーバーは受け取った
  `engine_log` を自分のログへ書くため、開発用サーバーはエンジンのマシンのログを見ずに推論の経過と失敗を読めます。
- サーバーはエンジンを起動・再起動しません。エンジンの再起動は systemd と開発担当が持ちます。
  エンジンに届かない要求は `503`、応答の途中で接続が切れた要求は `502` として返します。
  生成はモデルの取得を含めて長くかかるため、サーバーは応答待ちを打ち切りません (接続の確立だけ 5 秒で諦めます)。
- エンジンは `_run_generation` を呼んで WAV を返すだけです。辞書の置換・話速・記録・最終ファイルはサーバーが持ち、
  SQLite と `data/audio` へ書くのはサーバーだけです。
- ブラウザを閉じても生成は最後まで進み、記録されます。
- 推論エンジンが保持するモデルは 1 つです。モデル・機器・精度の組が変わると読み直します。
  画面と API の既定 (bf16 を扱える機器では bf16) をそろえ、交互に使っても読み直さないようにしています。
- torch.compile は使いません。RTX 3060 の実測では `dynamic=True` はコンパイルに失敗し、
  `dynamic=False` は初回 145 秒、文章の長さが変わるたびに 20〜36 秒の再コンパイルがかかりました。

## 記録とファイルの整合

生成では、推論エンジンから受け取った WAV を `data/tmp/<batch>/` に一時名で書き、そのまま仕上げます。
話速を変える場合は ffmpeg の `atempo` で一時ファイルに書き出します。
仕上がった WAV を `data/audio/<batch>_<候補番号>.wav` へ移し、その後に全候補の記録を 1 つのトランザクションで確定します。
記録に失敗したら移したファイルを消します。`data/tmp/<batch>/` は成否にかかわらず消します。

削除では、先に記録を消してからファイルを消します。
ファイルを消せなかった場合は `file_errors` に残し、履歴の画面に表示します。

## 読み辞書

読み辞書は SQLite の `dictionary` テーブルにあります。
データベースを新しく作るときだけ、Gradio 版の `config/reading_dictionary.json` を取り込みます。
元の JSON は変更・削除しません。取り込んだ後に辞書を空にしても、再び取り込むことはありません。

## 公開範囲

家庭内 LAN での利用 (level-1) を前提とし、サーバーにも推論エンジンにも認証はありません。アプリは次を守ります。

- 外部コマンド (ffmpeg) は引数の配列で呼び、shell を通しません。
- 保存するファイル名はサーバーが決めます。アップロード時のファイル名は表示にだけ使います。
- 参照音声は拡張子を限定し、50MB までにします。
- SQL はすべてパラメーターで渡します。

LoRA フォルダの指定は Gradio 版と同じく推論エンジンへそのまま渡し、エンジンのマシン上のパスとして扱います。
LAN 内の利用者を信頼する前提による判断で、公開範囲を広げるときに見直します。
